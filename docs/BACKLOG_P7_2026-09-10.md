# P7 요구사항 접수 (2026-09-10)

P6(클로드 블록 UI 개선) 작업 중 사용자가 전달한 원문 요구사항이다. **아직 설계 전**이며,
P6 완료 후 브레인스토밍 → 설계 → 구현 계획 순으로 진행한다. 여기서는 원문을 보존하고
1차 분류만 해 둔다.

## 원문

> (회사) 회사 업무중에 계속 리마인드가 필요한 메모 내용이 있음
> <예시>
> -미완료 할일
> -개발팀에서 공유한 일정
> -개발팀에서 공유한 확정사항
> -정책 결정사항 등
> 커뮤니케이션 섹션은 별도 표시 양식이 필요함. 다른 팀원이 질문한 내용을 확인후에 답변해야 하는 경우.
>
> (오류) 현재 텍스트유형+볼드 처리 중복으로 하면 텍스트가 두껍게 적용되는데 중복 적용 안되게 해줘 텍스트유형에 볼드 처리 있는 경우 추가로 볼드 적용해도 미적용되게
>
> 체크박스 체크처리 시에 필요하면 그 하위 텍스트 라인까지 빗금 처리 되게 옵션으로 처리가능하게 ctrl+체크박스 누르면 어떨까?
>
> 섹션하위에 위치한 섹션의 경우 시각적으로 위계가 좀더 구별가게 UI가 표시되면 좋겠음. 뎁스가 하위에 있다는 느낌이면 돼
>
> (오류) 섹션 하단에 섹션있을 경우 들여쓰기→하단 섹션추가 시에는 섹션 하위에 속해지는데 상위, 하위 섹션 사이에 신규로 들여쓰기 되지 않은 칸 추가했다 지울경우 하위 섹션이 상단 섹션에 속해지지 않는 오류 발생

## 1차 분류

| # | 종류 | 내용 | 비고 |
|---|---|---|---|
| A | 신규 기능 | 리마인드가 필요한 메모 내용의 상시 노출 (미완료 할일 / 개발팀 공유 일정 · 확정사항 / 정책 결정사항) | 범위가 가장 크고 모호하다. 브레인스토밍 필수 |
| B | 신규 기능 | 커뮤니케이션 섹션 전용 표시 양식 — "팀원 질문 → 확인 → 답변" 흐름 | A 와 묶일 수도, 별도 블록 유형일 수도 |
| C | 버그 | 텍스트 유형이 이미 볼드인 경우 추가 볼드가 이중 적용됨 | 재현·원인 확인 필요 (`spanFormat` / `headingLevel` 렌더 경로) |
| D | 신규 기능 | 체크박스 체크 시 하위 줄까지 취소선 — Ctrl+클릭 토글 제안 | 하위 판정에 P6 의 범위 판정 재사용 가능 |
| E | 신규 기능 | 섹션 하위 섹션의 위계를 시각적으로 구별 | **P6 T1 에서 중첩을 막 허용했으므로 그 후속이다** |
| F | 버그 | 상위/하위 섹션 사이에 들여쓰기 없는 칸을 넣었다 지우면 하위 섹션이 상위 섹션 소속에서 빠짐 | **P6 T1 의 범위 판정과 직결.** 지운 칸의 들여쓰기 복원 문제로 보인다 |

## 먼저 확인할 것

- **F 는 P6 T1 변경 이후 재현 여부를 다시 확인해야 한다.** T1 에서 "나보다 얕거나 같은
  헤더에서만 끊김"으로 바꿨으므로 증상이 달라졌을 수 있다.
- **E 는 P6 완료 직후가 적기다.** 중첩이 이제 데이터 모델에서 가능해졌는데 화면에는
  아무 표시가 없다.
- A · B 는 요구가 추상적이라 "무엇을 어디에 어떻게 보여줄지"를 사용자와 먼저 좁힌다.

### F — 재현 결과

보고된 시나리오(섹션 바로 아래 자식 섹션, 사이에 들여쓰기 없는 칸을 넣었다 맨 앞
Backspace 로 삭제)를 **P6 이전 커밋 `1e7b743` 에서 돌리면 재현되고, 현재 master 에서는
재현되지 않는다.** P6 이전에는 섹션 A 에 접기 버튼조차 생기지 않는다 — 자식이 하나도
없다는 뜻이다.

들여쓰기 값 자체는 수정 전후가 `[0,1]` → `[0,0,1]` → `[0,1]` 로 **같다.** 달라진 건 그
값을 읽는 `computeSectionBlockRange` 쪽으로, P6 T1 이 끊김 조건을 '다음 섹션 타이틀에서
무조건'에서 '나보다 얕거나 같은 들여쓰기의 헤더에서만'으로 일반화하면서 해결됐다.

**사용자는 아직 이 증상을 볼 수 있다** — 최신 릴리즈 v1.0.18 이 P6 이전이기 때문이다.
릴리즈하면 사라진다. 회귀 방지용으로 `e2e/section-nesting-restore.spec.ts` 를 남겼다.

### C — 측정 결과

볼드를 먼저 걸고 위계를 나중에 적용하는 순서에서 난다(위계를 먼저 걸면 `applyBoldSegment`
가 '켜기 불가'로 막는다). 계산된 스타일을 실제로 재 보니 두 방향의 결함이 있었다.

| 줄 종류 | 볼드 span | 나머지 글자 | 증상 |
|---|---|---|---|
| 위계 없음 | w=400 + 그림자 | w=400 | 정상 (faux-bold 가 굵기 역할) |
| H1 · H2 | **w=700 + 그림자** | w=700 | 이미 700 인데 그림자까지 → 더 두꺼움 |
| 섹션 타이틀 | **w=400** + 그림자 | **w=700** | 오히려 더 얇음 |

본문 볼드는 `font-weight` 가 아니라 faux-bold(`text-shadow`)로 표현된다는 점이 핵심이다.
섹션 타이틀은 CSS override 대상에서 빠져 있어 `.inline-bold` 의 기본 400 이 제목의 700 을
덮고 있었다. 둘 다 `font-weight: inherit` + `text-shadow: none` 으로 해결했다.

**데이터는 건드리지 않았다** — H3 처럼 볼드 span 을 지우면(`stripBoldForParenHeading`)
나중에 위계를 풀었을 때 볼드가 영영 사라진다. 토글 동작도 그대로 뒀다.
회귀 테스트: `e2e/heading-bold-double.spec.ts`

### 곁다리로 확인된 것

- **`Delete` 키는 칸을 앞으로 병합하지 않는다.** 줄 끝에서 `Delete` 를 눌러도 아래 빈 칸이
  지워지지 않는다(`Backspace` 만 동작). 의도된 것인지 확인이 필요하다.
- **줄 맨 앞에서 `Shift+Enter` 를 누르면 아래로 밀려난 줄이 자동 들여쓰기를 받는다.**
  섹션 타이틀 맨 앞에서 하면 그 섹션이 한 단 깊어지고, 칸을 지워도 되돌아오지 않는다
  (`[0,1]` → `[0,0,2]` → `[0,2]`). 반복하면 계속 깊어진다.

## E — 하위 섹션 위계 시각화 (2026-09-14, 구현 완료)

요구는 *"뎁스가 하위에 있다는 느낌이면 돼"* 였다. 중첩 섹션은 거터 폭만 넓어질 뿐
행 배경색·글자 크기가 최상위 섹션과 똑같아 깊이가 보이지 않았다.

**JS 는 건드리지 않았다** — `editor-line--level-N` 과 인라인 `--indent-level` 이 이미 모든
줄에 붙어 있어 `editor-line.css` 만으로 끝났다.

| 바뀐 것 | 내용 |
|---|---|
| 색 바 시작점 | 행 전체 단색 → `linear-gradient` 하드 스톱으로 `level × 20px` 부터 시작 |
| 거터 | `.editor-line--section-title .editor-line-gutter { background-color: transparent }` 삭제 → 드러난 거터가 본문 줄과 같은 들여쓰기 음영을 받는다 |
| 타이틀 글자 | level 0→16px, 1→15px, 2 이상→14px (본문 크기에서 멈춘다) |

색상 8종은 각자 `background` 를 선언하던 것을 `--section-bg` 변수로 바꿔 그라디언트 한 곳에서
읽게 정리했다. level 0 은 오프셋이 0px 이라 최상위 섹션은 이전과 픽셀 단위로 같다.

**`level` 은 원시 들여쓰기를 그대로 쓴다.** 섹션 중첩 깊이를 따로 계산하면 JS 변경이 생기고,
무엇보다 색 바 인셋이 어차피 원시 들여쓰기로 결정되므로 글자 크기가 다른 기준을 쓰면 둘이 따로 논다.

회귀 테스트는 `e2e/section-depth-visual.spec.ts` (5건). 구 CSS 로 빌드해 5건 전부 실패하는 것을
확인한 뒤 구현했다.

### 곁다리로 확인된 것 — 첫 줄을 섹션으로 만들면 색이 안 보인다

`editor.css` 의 `.editor-line--sticky-title` 이 흰 배경을 `background` 단축 속성으로 까는데,
특이도가 `.editor-line--section-title` 과 같고(클래스 1개) 번들에서 더 뒤에 온다
(빌드 산출물 기준 섹션 규칙 ~2.9KB, sticky 규칙 ~41.5KB 지점). 그래서 첫 줄에서는 섹션 색이
흰색에 덮인다.

**이번 변경과 무관한 기존 동작이다** — 구 CSS 에서도 같은 이유로 파란 배경이 덮였다. 첫 줄은
보통 메모 제목이라 드러나지 않았던 것으로 보인다. 고칠지는 아직 정하지 않았다.
이 때문에 `section-depth-visual.spec.ts` 의 섹션 사다리는 둘째 줄부터 쌓는다.

### D — 체크박스 체크 시 하위 줄까지 취소선

요구는 *"필요하면 그 하위 텍스트 라인까지 빗금 처리 되게 옵션으로, ctrl+체크박스"* 다.

- 현재 토글은 `Editor.tsx` 의 `handleLineCheckboxToggle` — **그 줄에만** `checkboxChecked`
  와 `strikethrough` 를 같이 켠다.
- `Checkbox.tsx` 의 `onToggle` 은 인자를 받지 않는다. Ctrl 여부를 넘기려면 `onToggle` 시그니처에
  이벤트나 플래그를 추가하고 `EditorLine.tsx:293-296` 배선도 같이 고쳐야 한다.
- '하위' 판정은 섹션과 같은 규칙(뒤따르는 연속된 더 깊은 들여쓰기 줄)이면 된다. 다만
  `computeSectionBlockRange` 는 `isBlockHeader` 인 줄만 받으므로 체크박스 줄에는 그대로 못 쓴다.
  헤더 조건을 뺀 일반 헬퍼로 뽑아내는 편이 맞다.
- 설계 때 정할 것: 하위 줄에 체크박스가 있으면 그것도 같이 체크할지(아니면 취소선만),
  Ctrl+클릭으로 해제하면 하위 취소선도 같이 풀지, Ctrl+클릭을 어떻게 알릴지(툴팁 등).
