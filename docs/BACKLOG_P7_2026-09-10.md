# P7 요구사항 접수 (2026-09-10)

P6(클로드 블록 UI 개선) 작업 중 사용자가 전달한 원문 요구사항이다. **아직 설계 전**이며,
P6 완료 후 브레인스토밍 → 설계 → 구현 계획 순으로 진행한다. 여기서는 원문을 보존하고
1차 분류만 해 둔다.

## 원문

> (회사) 회사 업무중에 계속 리마인드가 필요한 메모 내용이 있음
> <예시>
> -미완료 할일
> -개발팀에서 공유한 일정
> -개발팀에서 공유한 확정사항
> -정책 결정사항 등
> 커뮤니케이션 섹션은 별도 표시 양식이 필요함. 다른 팀원이 질문한 내용을 확인후에 답변해야 하는 경우.
>
> (오류) 현재 텍스트유형+볼드 처리 중복으로 하면 텍스트가 두껍게 적용되는데 중복 적용 안되게 해줘 텍스트유형에 볼드 처리 있는 경우 추가로 볼드 적용해도 미적용되게
>
> 체크박스 체크처리 시에 필요하면 그 하위 텍스트 라인까지 빗금 처리 되게 옵션으로 처리가능하게 ctrl+체크박스 누르면 어떨까?
>
> 섹션하위에 위치한 섹션의 경우 시각적으로 위계가 좀더 구별가게 UI가 표시되면 좋겠음. 뎁스가 하위에 있다는 느낌이면 돼
>
> (오류) 섹션 하단에 섹션있을 경우 들여쓰기→하단 섹션추가 시에는 섹션 하위에 속해지는데 상위, 하위 섹션 사이에 신규로 들여쓰기 되지 않은 칸 추가했다 지울경우 하위 섹션이 상단 섹션에 속해지지 않는 오류 발생

## 1차 분류

| # | 종류 | 내용 | 비고 |
|---|---|---|---|
| A | 신규 기능 | 리마인드가 필요한 메모 내용의 상시 노출 (미완료 할일 / 개발팀 공유 일정 · 확정사항 / 정책 결정사항) | 범위가 가장 크고 모호하다. 브레인스토밍 필수 |
| B | 신규 기능 | 커뮤니케이션 섹션 전용 표시 양식 — "팀원 질문 → 확인 → 답변" 흐름 | A 와 묶일 수도, 별도 블록 유형일 수도 |
| C | 버그 | 텍스트 유형이 이미 볼드인 경우 추가 볼드가 이중 적용됨 | 재현·원인 확인 필요 (`spanFormat` / `headingLevel` 렌더 경로) |
| D | 신규 기능 | 체크박스 체크 시 하위 줄까지 취소선 — Ctrl+클릭 토글 제안 | 하위 판정에 P6 의 범위 판정 재사용 가능 |
| E | 신규 기능 | 섹션 하위 섹션의 위계를 시각적으로 구별 | **P6 T1 에서 중첩을 막 허용했으므로 그 후속이다** |
| F | 버그 | 상위/하위 섹션 사이에 들여쓰기 없는 칸을 넣었다 지우면 하위 섹션이 상위 섹션 소속에서 빠짐 | **P6 T1 의 범위 판정과 직결.** 지운 칸의 들여쓰기 복원 문제로 보인다 |

## 먼저 확인할 것

- **F 는 P6 T1 변경 이후 재현 여부를 다시 확인해야 한다.** T1 에서 "나보다 얕거나 같은
  헤더에서만 끊김"으로 바꿨으므로 증상이 달라졌을 수 있다.
- **E 는 P6 완료 직후가 적기다.** 중첩이 이제 데이터 모델에서 가능해졌는데 화면에는
  아무 표시가 없다.
- A · B 는 요구가 추상적이라 "무엇을 어디에 어떻게 보여줄지"를 사용자와 먼저 좁힌다.
